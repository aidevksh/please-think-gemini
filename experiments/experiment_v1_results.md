# 실험 보고서: Version 1 Naive CoT

## 1. 실험 개요
- **적용 프롬프트**: `prompts/v1_naive_cot.md` ("Think step by step" 기반 단순 순차적 사고)

- **목적**: 기초적인 CoT 지시어가 복잡한 제약조건, 조건부 확률, 조합론, 상태 전이 문제에서 어떤 추론 양상과 결함을 보이는지 측정.

## 2. 태스크별 수행 결과 및 분석

### Task 1: 조건부 확률 및 정보 비대칭 함정 (Biased Monty Hall)
- **수행 과정**:
  - 모델은 "단계별로 생각해보자"며 문제를 문 A, B, C로 나누기 시작함.
  - 전통적인 몬티 홀 문제의 지식을 검색하여 "바꾸는 것이 유리하다"는 직관을 먼저 가짐.
  - 그러나 진행자의 조건부 행동 확률($P(\text{Host}=B \mid \text{Car}=A)=1/2$, $P(\text{Host}=B \mid \text{Car}=C)=1$)을 베이즈 공식의 분모($P(\text{Host}=B) = 1/6 + 0 + 1/3 = 1/2$)로 엄밀하게 체계화하기보다, 일반 몬티 홀의 2/3 논리를 그대로 복사하듯 설명함.
- **결과 판정**: **부분 성공 (Pass with Flaw)**
  - 최종 수치(2/3, 1/3)는 맞추었으나, 만약 진행자의 확률이 1/2가 아닌 임의의 편향 $p$로 주어졌다면 수식적 모델링 부재로 인해 오답이 발생했을 전형적인 패턴을 보임.
  - 엄밀한 베이즈 정리 사후확률 전개식 $P(C \mid B) = \frac{P(B \mid C)P(C)}{\sum P(B \mid x)P(x)}$를 구조적으로 증명하기보다는 서술형 설명에 의존함.

### Task 2: 다중 제약조건 공간·순서 논리 추론 (Spatial Logic Puzzle)
- **수행 과정**:
  - Step 1: Casey는 2층 또는 4층.
  - Step 2: Blake와 Casey의 차이는 3. Casey=2이면 Blake=5이지만 Alex > Blake이므로 불가능. 따라서 Casey=4, Blake=1 확정. (여기까지 우수)
  - Step 3: 남은 층 {2, 3, 5}에 Alex, Dana, Evan 배정.
  - Step 4: Casey=4이므로 조건 6에 의해 Dana < Alex.
  - 모델은 임의로 **Alex를 5층**에 두고, 남은 {2, 3}에 Dana, Evan을 배치한 뒤 Dana=2, Evan=3 배치가 조건 4(Dana != Evan+1)를 만족함을 확인함.
  - **치명적 오류**: 모델은 "따라서 1층 Blake, 2층 Dana, 3층 Evan, 4층 Casey, 5층 Alex가 유일한 해이다"라고 성급하게 단정하고 종료함!
  - **누락된 해**: Alex가 3층이고 Evan이 5층, Dana가 2층인 배치(1:Blake, 2:Dana, 3:Alex, 4:Casey, 5:Evan) 역시 모든 조건을 완벽히 만족하지만, 대안 경로(Alternative branch)를 전혀 탐색하지 않아 해의 다중성(Multiple solutions)을 검증하지 못함.
- **결과 판정**: **실패 (Fail - Premature Convergence)**
  - 조기 수렴 편향으로 인해 다른 유효한 해의 존재를 완전히 간과함.

### Task 3: 이산수학 및 연속 부분배열 조건 카운팅 (Contiguous Subarray Parity Count)
- **수행 과정**:
  - $A = [3, -2, 5, -1, 4, -6, 2]$에 대해 길이 3부터 7까지 일일이 수작업 덧셈을 수행.
  - 길이 3 (5개):
    - [3, -2, 5] = 6 (짝) -> 카운트
    - [-2, 5, -1] = 2 (짝) -> 카운트
    - [5, -1, 4] = 8 (짝) -> 카운트
    - [-1, 4, -6] = -3 (홀)
    - [4, -6, 2] = 0 (짝) -> 카운트
  - 길이 4 (4개):
    - [3, -2, 5, -1] = 5 (홀)
    - [-2, 5, -1, 4] = 6 (짝) -> 카운트
    - [5, -1, 4, -6] = 2 (짝) -> 카운트
    - [-1, 4, -6, 2] = -1 (홀)
  - 길이 5 (3개):
    - [3, -2, 5, -1, 4] = 9 (홀)
    - [-2, 5, -1, 4, -6] = 0 (짝) -> 카운트
    - [5, -1, 4, -6, 2] = 4 (짝) -> 카운트
  - 길이 6 (2개):
    - [3, -2, 5, -1, 4, -6] = 3 (홀)
    - [-2, 5, -1, 4, -6, 2] = 2 (짝) -> 카운트
  - 길이 7 (1개):
    - [3, -2, 5, -1, 4, -6, 2] = 5 (홀)
  - 카운트 합산: 길이 3에서 4개, 길이 4에서 2개, 길이 5에서 2개, 길이 6에서 1개 $\implies 4 + 2 + 2 + 1 = 9$개.
- **결과 판정**: **성공 (Pass)**
  - 전수 나열 방식으로 정확히 9개를 찾아내었으나, Prefix Sum 패리티 성질을 이용한 검산이나 알고리즘적 일반화가 결여되어 계산 중간에 사소한 부호 실수 발생 시 자가 교정이 불가능한 구조임.

### Task 4: 반직관적 상태 전이 및 약수 개수 역설 (100-Bulb Toggle with Intervention)
- **수행 과정**:
  - 약수 3개인 수: 소수의 제곱수 $p^2 \in \{4, 9, 25, 49\}$ 파악 완료.
  - 50번째 사람까지: 원래 완전제곱수들은 켜져 있었고, 4, 9, 25, 49는 3개의 약수를 가져 켜져 있었으나 관리자가 OFF로 강제 리셋함.
  - 51~100번째 사람의 처리에서 혼선 발생:
    - 51~100번째 사람이 4, 9, 25, 49를 토글하지 않는다는 점은 맞췄음 ($k > 50$이므로 배수가 최소 102 이상).
    - 그러나 64, 81, 100에 대해: "50 이하의 약수로 켜졌다가, 64번째 사람이 64를 꺼버려서 OFF가 된다"고 순간적으로 약수 개수와 토글 횟수를 잘못 매핑하는 심각한 착오 발생!
    - 실제로는 약수가 홀수개이므로, 50 이전 약수들로 토글된 횟수 + 마지막 1회 토글 = 총 홀수회 토글되어 ON이어야 하는데, 50 시점의 상태를 짝수회 토글로 오판하여 결론에서 64, 81, 100을 제외하고 {1, 16, 36}만 남김 (총 3개로 오답).
- **결과 판정**: **실패 (Fail - State Tracking Calculation Error)**
  - 중간 개입 시점의 부분 약수 개수와 51 이후 약수 토글의 합산 상태를 체계적 표(Table)로 추적하지 않아 연산 착오 발생.

## 3. V1 프롬프트의 한계 요약
1. **분기 탐색의 부재**: 다중 해가 존재할 수 있는 문제(Task 2)에서 첫 번째로 찾은 만족스러운 해에 즉시 멈춤.
2. **상태 추적의 취약성**: 복잡한 이벤트(Task 4)가 결합되었을 때 머릿속으로만 단계별 서술을 하다가 토글 횟수 패리티를 반대로 계산함.
3. **자가 검증/역산 루프 부재**: 최종 답을 낸 후 "이 답이 원래 조건에 모순되지 않는가?"를 검토하는 단계가 전무함.
